# Каркас UI

Каркас, в который встают блоки дашборда: токены, сетка, загрузка данных,
служебные состояния, шапка, состояние в URL и **контракт блока**. Самих блоков
здесь нет: карточки метрик описаны в [blocks-metrics](blocks-metrics.md), график
— в [blocks-dynamics](blocks-dynamics.md), рейтинг и heatmap — в
[blocks-antidrivers](blocks-antidrivers.md), прямая речь и инсайты — в своих
слайсах.

Связанные документы: [design-spec](design-spec.md) (замеры и палитра),
[design-validation](design-validation.md) (`V-xx`), [decisions](decisions.md)
(`D-xx`), [data-model §7](data-model.md#7-объём-и-стратегия-загрузки) (контракт JSON).

```
├── js/timeseries.js      интервалы и VOC временных рядов
├── js/chart-geometry.js  координаты, линии и области SVG-графика
├── js/antidrivers.js     рейтинг вклада и матрица по времени
├── js/dimensions.js      список измерений и вывод их значений из данных
├── js/labels.js          подписи из справочника с fallback на код

├── dev/contrast.html     самопроверка контраста токенов

```

Локальный запуск — статический сервер над `site/`:

```
python3 -m http.server 4173 --directory site
```

## Токены

Палитра, шкала отступов и типографика — CSS custom properties в
`css/tokens.css`. Остальные стили обращаются только через `var()`, поэтому
цветовой литерал вне этого файла — ошибка, а не вариант.

Гарнитура — системный стек, веб-шрифт не грузится (`D-30`).

Шкала отступов кратна `4` (`V-02`); между равноправными элементами — один
зазор `--gap-card`, а не смесь `8` / `12` / `16` из макета.

## Сетка

Страница обычная скроллящаяся: высота артборда `1342` ограничением не является,
блоки идут потоком и растут по содержимому. Вложенного вертикального скролла
внутри карточек нет.

Контентная колонка — `--content-max: 1400px`, обе контентные строки берут ширину
правого рейла из одного токена `--rail-width`, поэтому правые края совпадают по
построению, а колонки в сумме дают `1400` (`V-01`). Карточки растягиваются по
колонке и внутри одной колонки одной ширины (`V-03`).

Сетка fluid: `minmax` в grid и `max-width` контентной колонки (`D-29`). Ниже
`--content-min: 1200px` появляется горизонтальный скролл страницы — сетка не
ломается и порядок блоков не меняется.

### Значения, выбранные при реализации

Макет в этих местах воспроизводить нельзя, значения выбраны на нашей стороне:

| Что | Значение | Откуда |
| --- | --- | --- |
| Ширина правого рейла | `344` | вместо `338` в метриках и `346` в основной области (`V-01`) |
| Зазор между карточками и колонками | `16` | одна шкала вместо `8` / `12` / `16` (`V-02`) |
| Пропорция большой карточки к малой | `1.65 : 1` | отношение `356 : 216` из [design-spec §3](design-spec.md#3-строка-метрик-1400--201) |
| Порядок сегментных карточек | по числу оценок, убывание | в макете порядок `ММБ`, `СБ`, `КИБ` совпадает с объёмом; зашивать состав сегментов нельзя (`D-01`) |

## Контракт блока

Блоки следующих слайсов пишутся параллельно, поэтому интерфейс между каркасом и
блоком зафиксирован здесь. Незафиксированный интерфейс уже разводил две
параллельные сессии по манифесту — повторять этот опыт нечем.

### Реестр

Блок — модуль `js/blocks/<id>.js`, экспортирующий функцию отрисовки. Объявляется
одной строкой в массиве `BLOCKS` в `main.js`:

```js
{ id: 'voc-channel', title: 'VOC канала', host: 'metrics',
  modifier: 'card--metric card--metric-big', render: renderVocChannel },
```

| Поле | Значение |
| --- | --- |
| `id` | уникальный идентификатор, он же ключ в карте блоков |
| `title` | заголовок по умолчанию; блок вправе переопределить его сам |
| `host` | контейнер в `index.html`: `metrics`, `rail-top`, `main`, `rail-main` |
| `modifier` | CSS-модификаторы карточки |
| `render` | `(block, context) => void`; без него блок показывает заглушку слайса |

**Добавить блок = новый файл и одна строка в `BLOCKS`.** Правка существующих
строк не нужна, поэтому две ветки, добавившие разные блоки, сливаются без
конфликта содержимого.

### Объект контекста

`main.js` строит контекст **один раз на отрисовку** и передаёт **ту же ссылку**
всем блокам: разойтись в том, что считает срез, они не могут по построению.

| Поле | Что это |
| --- | --- |
| `rows` | все оценки выгрузки, без фильтров |
| `slice` | оценки после канала, периода и фильтров — то, что показывает дашборд |
| `previousSlice` | тот же срез за предыдущий аналогичный период (`D-23`, `D-24`) |
| `state` | `{ channel, preset, from, to, filters }` — разрешённое состояние, а не сырое из URL |
| `period` | `{ preset, from, to, complete }` текущего периода |
| `previousPeriod` | период сравнения той же формы |
| `reference` | `reference.json` целиком: `operations`, `plan`, `labels` |
| `label` | `(dimension, code) => string`, fallback на код (`D-02`) |
| `dimensions` | доступные измерения с их значениями (`D-13`) |
| `segments` | коды сегментов в порядке убывания объёма |
| `select` | `(overrides) => { rows, previous, period, previousPeriod }` — свой подсрез и его effective period, см. ниже |
| `setState` | `(next) => void`: записать состояние в URL и перерисовать всё |

`select` принимает частичное состояние поверх текущего и возвращает срез за оба
периода сразу. Без `from` и `to` он использует global period из URL. Пара
`from` / `to` задаёт local period блока, не меняя global period; только одна
граница считается ошибкой. Возвращённые `period` и `previousPeriod` всегда
описывают effective period именно этого результата:

```js
/* VOC сегмента ММБ независимо от того, какой фильтр по сегменту стоит сейчас */
const { rows, previous, period, previousPeriod } = context.select({
  filters: withFilter(state.filters, 'segment', ['ММБ']),
});
```

Тождество по построению: `context.slice` равен `context.select().rows`.

### Что блок обязан делать сам

- **Считать — только ядром.** `metrics.js`, `period.js`, `plan.js`, `round.js`,
  `sufficiency.js`. Не хватает функции — она добавляется в ядро вместе с тестом,
  а не считается на месте. Арифметика по `mark` внутри `js/blocks/` — дефект.
- **Форматировать — только `format.js`** (`D-20`). `Intl`, `toLocaleString` и
  `toFixed` в блоке — дефект.
- **Решать про «нет данных» самому.** Каркас держит `загрузка` и `ошибка` на
  всех блоках сразу; пустоту блок объявляет по **своему** подсрезу: сегмент
  может быть пуст там, где канал полон (`D-34`).
- **Убирать за собой пометку в шапке карточки.** `setNote` переживает смену
  состояния, поэтому каждая отрисовка либо ставит пометку, либо гасит её.

## Загрузка данных

Контракт — [data-model §7](data-model.md#7-объём-и-стратегия-загрузки).
`loader.js` держится тонким намеренно, и это уже оправдалось: сессия data
pipeline уточнила контракт (`files` стал массивом с `role`, появился
`reference.json`), и адаптация затронула loader, справочник подписей и реестр
измерений — без правок сетки, состояний и форматирования.

Порядок источников:

1. `site/data/manifest.json` — настоящая выгрузка;
2. `site/fixture/manifest.json` — синтетика, если выгрузки нет;
3. недоступны оба — состояние ошибки.

Имена файлов берутся из манифеста по полю `role`: они содержат хэш содержимого
(`D-36`), а конвертер удаляет файлы прошлых сборок. `ratings` и `reference`
загружаются при открытии страницы, `verbatim` — по требованию.

Манифест запрашивается с `cache: 'no-store'`: заголовки кэширования на Pages не
настраиваются, поэтому «не кэшировать манифест» обеспечивает страница — иначе
браузер возьмёт старый манифест и запросит по нему уже удалённые файлы.

**Fallback на фикстуру всегда виден в интерфейсе.** В шапке выводится пометка
«Демо-данные» с причиной. Молчаливый fallback недопустим: он маскирует
сломанный pipeline. Побочная польза — опубликованная страница остаётся живой,
пока pipeline не готов.

Важное следствие: манифест, который **есть**, но указывает на отсутствующий
файл, — это ошибка, а не повод перейти на фикстуру. Такой случай показывает
состояние ошибки с именем файла.

## Служебные состояния

У каждого блока три состояния помимо содержимого (`D-34`):

| Состояние | Когда | Что видно |
| --- | --- | --- |
| загрузка | до ответа на файл данных | скелетон и текст для screen reader |
| нет данных | в выбранном срезе нет ни одной оценки | «Нет данных за выбранный период» и подсказка |
| ошибка загрузки | манифест или файл данных недоступны | «Данные не загрузились» и причина с именем файла |

Состояния различаются текстом, а не только цветом, поэтому читаются в
grayscale (`D-26`).

## Состояние в URL

URL — единственный источник состояния, читается при загрузке (`D-31`).

| Параметр | Значение |
| --- | --- |
| `channel` | код канала |
| `preset` | семантика периода: один из пяти preset или `custom` |
| `from`, `to` | границы периода, `YYYY-MM-DD` |
| `segment`, `trigger`, `cp`, `product`, `domain` | значения фильтра через запятую |

Все параметры читаются при загрузке. Канал, период и каждый поддержанный фильтр
записываются в URL через `pushState`; Back / Forward восстанавливают весь срез.
Клик по сегментной карточке и контрол `Сегменты` изменяют один и тот же параметр.
Достроенное по умолчанию состояние дописывается в URL через `replaceState`,
поэтому ссылка полна и без явных параметров.

Период по умолчанию берётся из `manifest.period` (`D-41`) и раскрывается
`period.js` в календарный месяц: строка `YYYY-MM` не знает, полон ли месяц, а
без этого не работает выравнивание сравнения по числу дней (`D-24`).
Быстрые preset привязаны к `manifest.period.to`, а не к системной дате, чтобы
одна и та же выгрузка давала воспроизводимый срез.
`preset` хранится рядом с датами: иначе календарный месяц после Reload стал бы
`custom`-диапазоном и получил бы другой previous period (`D-23`, `D-24`).

Период правится руками, поэтому вывернутый диапазон приходит и после загрузки —
на `popstate`. Ядро на нём падает намеренно, и каркас переводит это в состояние
ошибки, а не в необработанное исключение.

## Шапка

- табы каналов генерируются по уникальным значениям канала в данных (`D-01`);
- подписи — из `labels` в `reference.json`, нет подписи — показывается код (`D-02`);
- фильтры `Роли` и `ФО` не выводятся (`D-13`);
- измерение называется «Триггеры», не «Сценарии» (`D-14`, `V-21`);
- разделители фильтров декоративные: пустые и скрытые от screen reader (`V-04`);
- период выделен размером, весом и рамкой — он главный элемент шапки;
- период раскрывает пять быстрых preset и custom range из двух нативных
  `date input`; неверный range показывает ошибку внутри popover и не меняет URL;
- каждый фильтр раскрывает checkbox-список с явными `Применить` и `Сбросить`;
  доступны только `segment`, `trigger`, `cp`, `product`, `domain` (`D-13`);
- дата актуальности берётся из `generated_at` манифеста (`D-35`);
- в контроле периода стоит **тот же** разрешённый период, по которому считают
  карточки: иначе шапка пишет границы выгрузки, а цифры показывают месяц.

Измерение без значений в данных не выводится: фильтровать нечем.

`КП` и `Продукты` выводятся из триггера через `operations` в `reference.json` по
паре (канал, триггер) — join только по триггеру дал бы неверный разрез
([data-model §3.2](data-model.md#32-справочник-триггер--кп--продукт)). Значения
внутри одной оценки дедуплицируются: несколько её триггеров могут сойтись в один
продукт (`data-model §5.2`).

В листе `labels` аналитик пишет измерение по-русски («канал», «сегмент»), а
браузер знает только канонические id (`channel`, `segment`, `problem_type`).
Приводит одно к другому конвертер — `LABEL_DIMENSIONS` в `tools/voc_schema.py`,
и неизвестное измерение роняет сборку (`D-39`). Русско-английского словаря в
`site/js/` нет намеренно: у соответствия один дом.

## Форматирование

Одна функция на весь дашборд (`D-20`): `ru-RU`, запятая как десятичный
разделитель, неразрывный пробел в разрядах, даты `dd.mm.yy`. Считаем в полной
точности, округляем только при выводе (`D-21`).

Две ловушки, из-за которых форматирование живёт в одном месте:

- часть сборок ICU группирует `ru-RU` узким пробелом `U+202F`, а не `U+00A0` —
  разделитель приводится к `NBSP` явно;
- `new Date('2026-05-12')` — UTC-полночь, и западнее Гринвича даёт предыдущий
  день, поэтому дата разбирается по частям строки.

## Доступность

Контраст текста — не ниже WCAG AA (`4.5:1`, крупный `3:1`), даже там, где в
макете подписи темнее (`D-28`). Проверяется страницей
[`site/dev/contrast.html`](../site/dev/contrast.html): она читает **живые**
токены, поэтому не может разойтись с реализацией, и содержит positive control —
пару с заведомо низким контрастом, которая обязана давать FAIL.

Служебные подписи макета проверку проходят: `#A4A4A5` на `#0B0B0D` даёт
`7.9 : 1`, то есть опасение из
[requirements §7](requirements.md#7-сквозные-вопросы-реализации) п. 2 не
подтвердилось. Ограничение нашлось другое: белый текст на `#FF376B` даёт
`3.5 : 1`, поэтому на акцентной заливке текст тёмный (`--color-on-accent`).

Цвет не единственный носитель смысла (`D-26`): активный таб отличается рамкой,
фоном и весом шрифта; применённый фильтр — подчёркиванием и текстом выбранного
значения или количества. Триггеры popover публикуют `aria-expanded`, сами
панели имеют роль `dialog`, значения фильтров остаются нативными checkbox.
`Escape` закрывает popover и возвращает фокус на триггер. Критерий приёмки —
каркас читается в grayscale.
